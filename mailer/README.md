# Почтовый сервис ПРИЁМКИ

Небольшой backend, который принимает снимок реестра из [ПРИЁМКИ](https://ervsed.github.io/priemka-materialov/), хранит его в зашифрованном виде и отправляет отчёты по расписанию через SMTP.

Письмо содержит:

- HTML-отчёт с материалами за выбранный период и итогами по единицам;
- CSV-вложение для Excel;
- зашифрованную резервную копию реестра `.json` (пароль в письмо не входит).

Получатель, частота, время, часовой пояс и период данных задаются в настройках приложения. SMTP-пароль хранится только в окружении сервиса и никогда не попадает в браузер.

## Что нужно

- Node.js 20+ или Docker;
- SMTP-доступ (например, отдельный ящик на вашем почтовом домене, Gmail с паролем приложения, Яндекс Почта и т. п.);
- HTTPS-адрес для сервиса — GitHub Pages статический и не может сам отправлять почту.

## Быстрый старт

```bash
cd mailer
npm ci
cp .env.example .env
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Полученную строку вставьте в `.env` как `MAIL_API_TOKEN`. Заполните SMTP-параметры и запустите:

```bash
npm start
```

Проверка: `http://localhost:8787/health`.

### Docker

```bash
cp .env.example .env
# заполните .env
docker compose up -d --build
```

Каталог `./data` должен быть на постоянном диске. Сервис хранит состояние в одном файле `data/state.bin`. Не запускайте несколько реплик на одном файле.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт сервиса, по умолчанию `8787`. |
| `HOST` | Интерфейс прослушивания, по умолчанию `0.0.0.0`. |
| `MAIL_API_TOKEN` | Секретный ключ API. Минимум 24 символа. Он же используется для шифрования состояния на диске. |
| `ALLOWED_ORIGINS` | Список Origin через запятую. Для этого сайта: `https://ervsed.github.io`. |
| `SMTP_HOST` | SMTP-сервер. |
| `SMTP_PORT` | Порт: `587` (STARTTLS) или `465` (TLS). |
| `SMTP_SECURE` | `true` для порта 465, обычно `false` для 587. |
| `SMTP_REQUIRE_TLS` | Требовать STARTTLS. Обычно `true` для 587. |
| `SMTP_USER`, `SMTP_PASS` | SMTP-логин и пароль приложения. Оставьте пустыми, если SMTP без авторизации. |
| `SMTP_FROM` | Отправитель, например `"ПРИЁМКА <robot@example.com>"`. Домен отправителя должен разрешать отправку через ваш SMTP. |
| `SMTP_REPLY_TO` | Необязательный Reply-To. |
| `DATA_DIR` | Каталог состояния, по умолчанию `./data`. |
| `SCHEDULER_TICK_MS` | Период проверки расписания, по умолчанию `30000`. Минимум 5000. |

Для Gmail используйте не основной пароль, а [пароль приложения](https://support.google.com/accounts/answer/185833). SMTP-провайдеры могут ограничивать количество писем и требовать верифицированный домен отправителя.

## Подключение HTTPS

Сервис должен быть доступен браузеру по HTTPS. Проще всего поставить его за Caddy или nginx. Пример Caddy:

```caddyfile
mail.example.com {
    reverse_proxy 127.0.0.1:8787
}
```

В `ALLOWED_ORIGINS` добавьте точный Origin сайта:

```env
ALLOWED_ORIGINS=https://ervsed.github.io
```

Если вы размещаете копию фронтенда на другом домене, добавьте и его. Не используйте `*` в публичной установке.

## Настройка в приложении

1. Откройте **Настройки → Почта и отчёты → Настроить**.
2. Укажите email получателя, частоту (ежедневно / еженедельно / ежемесячно), день и время, а также данные за период (сегодня / 7 дней / 30 дней / всё время).
3. В блоке **Подключение к почтовому серверу** укажите:
   - адрес: `https://mail.example.com`;
   - ключ доступа: значение `MAIL_API_TOKEN`.
4. Нажмите **Сохранить настройки**. Статус покажет следующую отправку.
5. Нажмите **Отправить тест** — тестовое письмо придёт на указанный email.

Для локальной разработки по HTTP разрешены только `localhost`/`127.0.0.1`. В публичной установке нужен HTTPS.

## API

Все защищённые методы требуют заголовок `Authorization: Bearer <MAIL_API_TOKEN>`.

- `GET /health` — состояние сервиса без секретов.
- `GET /api/status` — текущее расписание и последняя ошибка.
- `POST /api/sync` — сохранить настройки и актуальный снимок; при `enabled: false` удалить данные и остановить расписание.
- `POST /api/test` — отправить тестовое письмо без изменения расписания.

Тело запроса `sync`:

```json
{
  "config": {
    "enabled": true,
    "email": "manager@example.com",
    "frequency": "weekly",
    "time": "18:00",
    "timezone": "Europe/Moscow",
    "weekday": 5,
    "dayOfMonth": null,
    "range": "7",
    "attachArchive": true
  },
  "snapshot": {
    "username": "admin",
    "generatedAt": "2026-10-26T12:00:00.000Z",
    "archivedCount": 0,
    "records": [
      {
        "date": "2026-10-26",
        "name": "Гипсокартон",
        "unit": "лист",
        "qty": 24,
        "note": "Накладная № 148"
      }
    ]
  },
  "archive": {
    "format": "priemka-backup",
    "version": 1,
    "account": {}
  }
}
```

Сервис проверяет все поля и ограничивает размер запроса.

## Безопасность и данные

- SMTP-пароль хранится только в `.env`/секретах хостинга.
- `MAIL_API_TOKEN` передаётся из приложения в заголовке Authorization и хранится в зашифрованном vault браузера.
- Состояние на диске (`data/state.bin`) зашифровано AES-256-GCM ключом, производным от `MAIL_API_TOKEN` через scrypt. В файле нет открытых имён материалов и email получателя.
- Для формирования отчёта сервис получает **незашифрованный снимок** реестра по HTTPS и держит его в памяти. Это необходимо для отправки читаемого отчёта по расписанию. Если это неприемлемо, отправляйте только зашифрованную копию — для этого потребуется доработать формат письма.
- Письмо содержит читаемый отчёт. Оно проходит через SMTP-провайдера; учитывайте это.
- Зашифрованная копия во вложении открывается паролем реестра. Пароль не отправляется.
- Отключение автоматической отправки в приложении очищает снимок и копию на сервере.
- Состояние одного сервиса рассчитано на один реестр. Для нескольких независимых пользователей разверните отдельные экземпляры.
- Смена `MAIL_API_TOKEN` делает существующий `data/state.bin` нечитаемым. Чтобы сменить токен, удалите `state.bin` и заново сохраните настройки из приложения.

## Разработка и тесты

```bash
npm ci
npm test                  # расчёт расписания, отчёт, валидация, шифрование состояния
npm run test:integration  # настоящая SMTP-отправка на локальный тестовый SMTP + планировщик
```

Интеграционный тест не требует внешнего почтового провайдера и не отправляет письма в интернет: он поднимает локальный SMTP-приёмник.

## Ограничения

- Возможна одна копия сервиса на один файл состояния.
- Планировщик работает, пока контейнер запущен. Если сервер был выключен в момент отправки, письмо уйдёт при следующем запуске.
- Время отправки рассчитывается по часовому поясу, сохранённому из браузера. При смене часового пояса откройте настройки почты и сохраните их заново.
- Нет вложений больше лимита вашего SMTP-провайдера. По умолчанию архив ограничен 8 МБ при приёме и 12 МБ при отправке.
