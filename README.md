# ПРИЁМКА

Реестр материалов, поступающих на объект. Дата, наименование, единица измерения и количество — без лишней бюрократии, случайных удалений и потерянных строк.

**Живая версия:** https://ervsed.github.io/priemka-materialov/
**Почтовый сервис:** [mailer/README.md](mailer/README.md) — разворачивается отдельно.

![Реестр материалов](docs/dashboard.png)

## Возможности

- **Быстрая регистрация.** Дата подставляется автоматически, единицы измерения выбираются в один клик.
- **Редактирование с историей.** У каждой записи хранится до 40 последних действий. После сохранения изменение можно сразу отменить одной кнопкой.
- **Без безвозвратного удаления.** В приложении нет функции удаления записи. Можно только переместить её в архив, подтвердив действие текущим паролем. Из архива запись возвращается в реестр.
- **Вход по логину и паролю.** Пароль не передаётся на сервер: на его основе в браузере создаётся ключ шифрования.
- **Шифрование AES-256-GCM.** Реестр хранится в `localStorage` только в зашифрованном виде. PBKDF2-SHA-256: 310 000 итераций, случайная соль.
- **Блокировка.** После 30 минут бездействия сессия закрывается, ключ удаляется из памяти.
- **Резервные копии и CSV.** Зашифрованная копия восстанавливается на чистом устройстве; текущая выборка выгружается в Excel.
- **Почта по расписанию.** Настраиваемый email, ежедневная / еженедельная / ежемесячная частота, время и часовой пояс, данные за сегодня / 7 / 30 дней / всё время. В письме — HTML-отчёт, CSV и зашифрованная копия реестра.
- **Поиск, период, итоги по единицам.** Суммы не смешиваются между разными единицами измерения.
- **Адаптивность и офлайн-доступ.** PWA-оболочка кэшируется service worker-ом.

## Быстрый старт

1. Откройте [живую версию](https://ervsed.github.io/priemka-materialov/).
2. При первом запуске создайте логин и пароль (минимум 8 символов).
3. Нажмите **«Принять материал»** и заполните дату, наименование, единицу и количество.
4. Сразу скачайте резервную копию: **Настройки → Скачать копию**.

Пароль невозможно восстановить: он не хранится на сервере. Без резервной копии данные нельзя вернуть после очистки браузера.

## Почта по расписанию

GitHub Pages раздаёт только статический сайт и не может сам отправлять письма. Для почты добавлен небольшой backend в папке [`mailer/`](mailer/) (Node.js + SMTP), который разворачивается на любом хостинге с HTTPS.

1. Разверните [`mailer/`](mailer/) по [инструкции](mailer/README.md), задайте SMTP-сервер, отправителя и секретный `MAIL_API_TOKEN`.
2. В приложении откройте **Настройки → Почта и отчёты → Настроить**.
3. Укажите email получателя, частоту, время и период данных.
4. В блоке **Подключение к почтовому серверу** вставьте HTTPS-адрес сервиса и `MAIL_API_TOKEN`.
5. Сохраните настройки и отправьте тестовое письмо.

Письмо содержит:

- HTML-отчёт с материалами за выбранный период и итогами по единицам;
- CSV для Excel;
- зашифрованную `.json`-копию реестра. Пароль от неё в письмо не входит.

Расписание работает на сервере, поэтому письма продолжают уходить, когда сайт закрыт. Если сервер был выключен в момент отправки, письмо уйдёт при следующем запуске. SMTP-пароль хранится только в окружении сервера. Снимок реестра, необходимый для читаемого отчёта, передаётся на ваш сервер по HTTPS и хранится там зашифрованным ключом, производным от `MAIL_API_TOKEN`.

## Защита от удаления

- Кнопки «Удалить» нет ни в интерфейсе, ни в коде приложения.
- Архивация требует повторного ввода текущего пароля.
- В архиве данные остаются на месте; запись можно вернуть.
- Все изменения фиксируются в истории; последнее изменение можно отменить.
- Восстановление резервной копии поверх существующего реестра заблокировано: импорт доступен только при первом запуске на чистом устройстве.

## Где хранятся данные

Без включённой почты приложение полностью клиентское: GitHub Pages отдаёт статические файлы, а пароль и материалы остаются в браузере.

- Реестр и настройки почты хранятся в `localStorage` текущего браузера в зашифрованном виде.
- На время активной вкладки ключ находится в памяти и в `sessionStorage`, чтобы страница переживала перезагрузку. При закрытии вкладки или блокировке ключ удаляется.
- Записи **не синхронизируются между устройствами автоматически**. Для переноса используйте резервную копию.
- При включённой автоматической почте снимок реестра отправляется на ваш почтовый сервис. Отключение отправки очищает снимок и архив на сервере.
- Очистка данных сайта в браузере удаляет локальный реестр. Без резервной копии восстановить его невозможно.
- Если пароль забыт, расшифровать данные нельзя. Резервную копию можно открыть на чистом устройстве старым паролем.

### Ограничения безопасности

Вход по паролю и шифрование защищают данные от случайного доступа на общем устройстве и от утечки через статический хостинг. Они не заменяют защиту операционной системы: злоумышленник с полным доступом к разблокированному профилю браузера или вредоносным расширением может получить доступ к данным.

При включении почты читаемый отчёт покидает браузер: он передаётся вашему серверу и затем идёт через SMTP-провайдера. Для конфиденциальных данных используйте собственный сервер и проверенного почтового провайдера.

## Локальный запуск

Сайту нужен HTTP(S)-контекст для Web Crypto и service worker:

```powershell
python -m http.server 8080
```

Откройте `http://localhost:8080/`.

## Тесты

Фронтенд проверялся в Chromium: вход, добавление, редактирование и отмена, архивация с паролем, восстановление, смена пароля, резервные копии, CSV, офлайн-режим, почтовые настройки и синхронизация.

Backend:

```bash
cd mailer
npm ci
npm test
npm run test:integration
```

Интеграционный тест поднимает локальный SMTP-приёмник и проверяет тестовое письмо, вложения, планировщик, CORS и шифрование состояния.

## Публикация на GitHub Pages

Публикация идёт из ветки `main`, корневой папки. В настройках репозитория:

**Settings → Pages → Build and deployment → Deploy from a branch → `main` / `/ (root)`**

Файл `.nojekyll` уже добавлен.

## Технологии

Чистый HTML, CSS и JavaScript без сборщика. Web Crypto API, localStorage/sessionStorage, service worker. Backend: Node.js 20, SMTP через Nodemailer, планировщик с IANA-часовыми поясами, шифрование состояния на диске. Шрифт Manrope — SIL Open Font License.
